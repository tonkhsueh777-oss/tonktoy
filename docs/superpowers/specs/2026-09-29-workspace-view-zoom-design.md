# PS 式工作区视图缩放设计

日期：2026-09-29
仓库：`tonkhsueh777-oss/tonktoy`

## 目标

把当前“局部放大镜”替换成 Photoshop 式的整工作区缩放，用于高精度裁切、参考线对齐和 1px 级校准。

用户要达到的效果：

- 点击 `− / 100% / +` 时，整张编辑工作区一起缩放。
- 原图、白色裁切框、固定尺标、蓝色参考线、尺寸标签一起视觉放大/缩小。
- 缩放只影响编辑视图，不改变原图实际尺寸、不改变裁切尺寸、不改变最终导出尺寸。
- 尺标数值、参考线坐标、白框坐标始终使用同一套“工作区逻辑坐标”。
- 在 200% / 400% 下，参考线和白框仍能按真实像素精确吸附。
- 原图拖动、白框拖动、参考线拖动在任意视图倍率下都保持准确。
- 移除现有局部放大镜预览，避免和工作区缩放概念冲突。

## 当前问题

当前编辑器的坐标和交互分散在多个脚本中：

- `app.js`：原图位置、原图缩放、导出裁切。
- `drag-fix.js`：尺标、白框边界、拖动/拉伸。
- `precision-crop.js`：白框锁定、吸附与部分拖动。
- `guides.js`：固定尺标参考线、原图锁定。
- `origin-align.js`：原图左上角对齐尺标原点。
- `magnifier.js`：局部放大镜。

如果只给 DOM 加 `transform: scale()`，鼠标坐标仍是屏幕坐标，而内部状态仍是未缩放逻辑坐标，会造成拖动、吸附、尺标和白框偏移。

## 方案 A

新增一层统一“视图倍率”状态，所有编辑状态继续保存在 100% 逻辑坐标中，屏幕显示才乘以倍率。

核心原则：

```text
逻辑坐标 = 永久稳定的数据层
视图倍率 = 仅影响显示
屏幕坐标 = 逻辑坐标 × viewZoom
鼠标移动量对应逻辑移动量 = 屏幕移动量 ÷ viewZoom
```

### 统一状态

新增：

```js
S.viewZoom = 1;
```

建议倍率：

- 50%
- 75%
- 100%
- 125%
- 150%
- 200%
- 300%
- 400%

默认 100%。

## 视觉结构

编辑区改为两层：

```text
editorViewport        // 可滚动的外壳，不缩放
└── editorWorkspace   // 逻辑画布，统一缩放
    ├── 尺标
    ├── 原图
    ├── 裁切框
    ├── 参考线
    └── 标签
```

`editorWorkspace` 保存固定逻辑宽高。

显示时使用：

```css
transform: scale(var(--view-zoom));
transform-origin: 0 0;
```

外层 `editorViewport` 的滚动尺寸显式设置为：

```text
workspaceLogicalWidth  × viewZoom
workspaceLogicalHeight × viewZoom
```

这样 200% 后可以滚动查看画布，不需要改变任何内部逻辑坐标。

## 坐标转换

新增两个统一工具函数：

```js
function clientToWorkspace(clientX, clientY)
function workspaceToClient(x, y)
```

所有以下操作必须通过这两个函数：

- 拖原图
- 拖白框
- 拉白框四边/四角
- 拖参考线
- 从尺标新建参考线
- 吸附检测
- 放置尺寸标签

禁止每个模块自己再计算缩放倍率。

## 尺标行为

尺标继续固定在工作区的 `0,0` 原点。

视图放大时：

- 尺标视觉也一起放大。
- 刻度之间在屏幕上的距离变大。
- 刻度代表的数值不变。
- `X=713` 在所有倍率下仍是逻辑坐标 713。

工作区拖动原图时：

- 尺标不动。
- 参考线不动。
- 只有原图图层移动。

## 参考线与吸附

参考线保存逻辑坐标，不保存 CSS 像素位置：

```js
{ axis: 'v', value: 713 }
{ axis: 'h', value: 245 }
```

显示时再根据工作区逻辑尺寸换算位置。

吸附判定使用逻辑坐标。

吸附容差采用“视觉容差固定”的方式：

```js
logicalSnapDistance = 12 / S.viewZoom;
```

因此：

- 100% 时约 12px 屏幕距离会吸附。
- 200% 时逻辑距离缩成 6px，但屏幕仍约 12px。
- 400% 时逻辑距离约 3px，适合精细定位。

这样放大越多，真实像素精度越高。

## 白框行为

白框永远保存逻辑坐标：

```js
S.crop = { x, y, width, height }
```

视图缩放不改变这些值。

“锁定裁切框大小”仍然有效：

- 开启后：只能移动 `x/y`。
- `width/height` 不变。
- 视图倍率改变时白框只是看起来变大/变小。

## 原图行为

原图位置和图片自身缩放继续使用现有 `S.view`。

需要明确区分两个缩放：

### 原图缩放

改变构图中的图片大小：

```text
S.view.scale
```

影响最终裁切内容。

### 工作区视图缩放

只改变编辑器视觉倍率：

```text
S.viewZoom
```

不影响导出。

UI 文案必须区分：

- 下方旧滑杆：`原图缩放`
- 上方新控制：`视图 100%`

## UI

删除现有：

- `magnifier.js`
- 左侧“放大预览”区域
- 工具栏“放大镜 2×”按钮组

新增工具栏：

```text
[ − ] [ 100% ] [ + ]
```

点击百分比可弹出简单倍率菜单：

```text
50%
75%
100%
125%
150%
200%
300%
400%
```

快捷行为：

- `−`：退到前一个倍率。
- `+`：进到下一个倍率。
- 默认 100%。

可选后续快捷键，不放进本次 V1：

- `Cmd/Ctrl + +`
- `Cmd/Ctrl + -`
- `Cmd/Ctrl + 0`

## 缩放中心

V1 采用稳定、可预测的规则：

- 改变倍率时，以当前视口中心作为锚点。
- 缩放后尽量保持原本视口中心对应的逻辑位置仍在屏幕中心。

这样不会每次点 `+` 后跳回左上角。

## 迁移原则

本次不重做裁切和导出算法。

重点是把“显示倍率”从数据坐标中拆开，避免再次出现：

- 尺标跟着图片移动
- 白框和参考线吸附偏位
- 放大后拖动距离翻倍
- 浏览器窗口变化后坐标跳动
- 原图尺寸被视图倍率误改

## 验收标准

### 视图缩放

1. 新图载入后默认显示 100%。
2. 点击 `+` 到 200% 时，整个工作区视觉放大 2 倍。
3. 点击 `−` 回到 100% 时，所有逻辑位置完全恢复一致。
4. 视图倍率变化后，导出的图片像素尺寸不改变。

### 尺标

1. 尺标 `0,0` 永远固定在工作区左上角。
2. 拖动原图时尺标不移动。
3. 200%/400% 时尺标数值仍准确。

### 参考线

1. `X=713` 的参考线在任何倍率下都代表同一个逻辑位置。
2. 放大到 400% 后移动参考线，数值变化可精确到 1px。
3. 参考线不随原图拖动。

### 白框

1. 100% 下白框 X/Y/W/H 与 400% 下完全一致。
2. 400% 下拖 4 个屏幕像素，应约等于 1 个逻辑像素。
3. 白框吸附到参考线后，其逻辑坐标严格等于参考线坐标。
4. “锁定裁切框大小”开启后，视图缩放不会改变白框 W/H。

### 原图

1. 原图自己的缩放滑杆仍只改变图片构图大小。
2. 工作区 `200%` 不改变 `S.view.scale`。
3. 原图锁定功能继续有效。

## 测试重点

需要覆盖以下回归：

- 100% → 200% → 400% → 100%，裁切坐标不漂移。
- 400% 下拖动白框到参考线，吸附后坐标准确。
- 400% 下拖动原图，尺标和参考线不移动。
- 浏览器窗口缩放后，逻辑坐标不改变。
- 视图倍率变化后点击“确认裁切”，导出结果与倍率无关。
- 原图锁定、白框大小锁定、参考线开关、吸附开关均能继续工作。

## 不在本次范围

- Canvas 重写整个编辑器。
- 无限画布。
- 多图层。
- PS 风格导航器面板。
- 快捷键体系完整复刻。

本次只解决一个核心目标：让高精度裁切所需的“整工作区缩放”稳定、准确，并和现有尺标/参考线/吸附共用同一套坐标。
